# AI 整理任务

Pasteory 0.1.46 起，正式整理使用文件任务 Agent。一次任务将全部选定资料导出到一个 `items.json`，模型自行决定读取、检索和整理方式。应用不再先抽样规划主题，也不再逐批发送资料。最近内容仍按设置中的 Top N 选取；全库任务包含所有可参与分析的资料。

## 任务目录

任务保存在应用数据目录的 `AITasks/<任务 ID>.agent/`：

```text
PROMPT.md                 本轮完整指令和用户偏好
task.json                 模型、范围和资源读取设置
items.json                全部正文、备注、版本及原路径引用
plan.schema.json          输出格式
existing/groups.json      数据库中实际存在的 AI 分组
existing/saved-plan.json  未确认的旧草稿，仅供参考
output/plan.json          Agent 提交的原始方案
output/validated-changes.json  校验后供用户应用的变更
scratch/                  Agent 的脚本与中间结果
trace/                    完整工具返回
agent-state.json          可继续的会话状态
execution.jsonl           增量执行、模型回复和用量记录
history.json              状态、范围和模型用量
```

文字和备注保留完整内容。图片和文件使用已有原路径，文件资料同时提供所在目录和可访问状态；任务不会复制这些资源。HTML 中单张内嵌图片改为同一剪贴板已有图片版本的路径引用，并记录原始 HTML 表示 ID。

“允许 Agent 读取原路径图片和文件”控制原资源读取。开启后，模型可按需读取本次引用的图片和文件；关闭后只能使用导出文字和元数据。本地 OCR 文字另由原有开关控制。逐条禁止 AI 的资料与检测到的密钥不会进入可分析内容。

## 执行与继续

Agent 可读取文件、检索完整 JSON、写入方案和执行本地脚本。脚本不能联网，只能写入本轮 `output/` 和 `scratch/`，原资源只读。工具返回过大时保留完整结果文件并给出继续读取的位置。模型会话达到单次输入预算时压缩旧上下文；已读取的工具结果和中间文件仍保留在目录中。

暂停后，选择“继续上次任务”会使用同一个任务目录和已保存会话。旧版本的批次任务会转为完整文件任务，旧方案保留为未确认的参考。模型、推理强度与预算继续使用应用设置；`auto` 表示不发送推理强度参数，由服务端决定，不继承开发用 Codex 会话的强度。

任务轮数和每日 token 预算仍有效。达到限制或请求失败时保存进度，可调整预算后继续。失败或超时的未知用量仍保守估算。空闲整理继续遵守时间窗口、每晚资料数、时长和 token 限制。

## 校验与应用

主题数量遵守用户保存的设置：目标值可在 6～8 个之间调整，最多 8 个，内容充分时保持 6～8 个主题，每个新主题至少有 3 条不同资料支持。资料不足时可少于 6 个，不创建空组凑数。这些设置同时写入 Prompt、任务清单和输出 Schema，并由应用校验。读取与检索方式仍由 Agent 自行决定。旧草稿中的组 ID 不属于已有分组；只有 `existing/groups.json` 中的 ID 可以复用，新组必须明确创建。每条输入必须有且只有一条分类结果，未分组也需要原因。组成员与概况引用必须有效，并尊重用户排除项。

分析期间内容变化时，保留其他条目的结果，将变化条目跳过并重新入队；概况如果引用了变化条目，也会一并跳过。用户检查后，应用仍以版本校验和事务统一写入，保持原文、备注、手动文件夹、收藏、置顶和使用时间，支持撤销。

任务完成、忽略或放弃后保留历史。存储看板单列“AI 任务历史”，按任务实际文件占用统计，不重复计算原路径资源。模型用量按实际请求记录；缓存输入和推理输出分别属于输入、输出的子集，不额外叠加。

整理预览按分组展示一份方案，显示组数、归类数和未分组数。同一组的新建、成员与概况操作合并为一张卡片，不把底层数据库操作数当作分组数。

旧版超出组数上限的方案会保留，但不能直接应用。点击“继续修正这份方案”会沿用原任务目录和 Agent 会话，按当前设置继续生成方案；原来的方案归档到 `revisions/`，不会自动应用或扩展为新复制的资料。
