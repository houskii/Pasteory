# 来源详情采集

Pasteory 把“剪辑内容”和“每次复制时的来源详情”分开保存。这样，即使相同内容在 60 秒内被合并为同一条剪辑，每一次复制仍然可以保留不同的网页或会话上下文。

## 开关与隐私边界

- 所有来源详情开关默认关闭。
- Chrome 网站默认全部允许。需要过滤时，在 Chrome 工具栏的 Pasteory 插件里关闭对应网站。
- 开关关闭时，对应策略不会运行。关闭开关只影响之后的复制，不会删除已经保存的数据。
- 微信和飞书只读取当前会话标题及标题栏里的会话类型信号，不保存 AX 树，也不读取消息正文。
- Chrome 插件没有 MutationObserver 或 DOM 轮询。只有复制事件发生且网站已允许时，才会读取当前选区和有限的附近元素。
- 设置页使用 Chrome、微信和飞书的真实应用图标。构建 App 时会把本机安装包里的 `.icns` 复制到 Pasteory 自己的资源目录，运行时优先读取随包资源。

## 当前策略

| 一级来源 | 应用 | 策略 | 保存内容 |
| --- | --- | --- | --- |
| 浏览器 | Chrome | `chrome.extension.web-context.v1` | 原始 URL、网站名、页面标题、选中内容、选中 HTML、有限的父级与相邻元素 |
| 浏览器 | BITS 网页 | Chrome 策略内的站点适配器 | 额外识别项目 ID、合码请求 ID、仓库、源分支、目标分支 |
| 通信软件 | 飞书 | `lark.ax.conversation.v1` | 对话类型、对话标题；人数可选采集但暂不展示 |
| 通信软件 | 微信 | `wechat.ax.conversation.v1` | 对话类型、对话标题；人数可选采集但暂不展示 |

## 数据模型

- `clips`：去重后的剪辑内容，标题和备注仍是用户编辑字段。
- `clip_capture_events`：每一次复制事件，关联当时的来源应用和可选来源详情。
- `context_entities`：可聚合的会话、网站、页面、仓库和分支。
- `capture_event_entities`：复制事件与聚合实体的关联。

聚合查询同时返回“不同剪辑数”和“复制事件数”。同名会话目前只在各自 Provider 内按显示名聚合，不会把它直接推断成某个联系人。

## Chrome 安装

Pasteory 启动时会自动注册 Chrome 原生消息桥。首次安装本地插件仍需在 Chrome 中确认：

1. 打开“设置 → 高级诊断 → Chrome 插件”。
2. 点击“准备 Chrome 插件”。Pasteory 会重新注册原生消息桥、复制插件目录，并打开 `chrome://extensions`。
3. 打开“开发者模式”，点击“加载已解压的扩展程序”，粘贴插件目录并选择。
4. 回到“采集与隐私”打开 Chrome 总开关。所有网站默认允许，需要过滤时在插件弹窗中逐站关闭。

扩展通过长连接复用原生进程，并在空闲 60 秒后断开。单次消息和落盘数据都有大小上限；超过限制时会拒绝，不会阻塞普通剪贴板保存。
