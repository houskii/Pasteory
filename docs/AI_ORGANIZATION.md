# AI 整理预览版

这一版在原生 macOS 应用中提供模型配置、智能分组、资料聚合、带依据的归纳，以及内容生命周期和共享载荷的无损压缩。AI 默认关闭，自动压缩默认关闭。源码通过独立开发分支和草稿 PR 交付；QA 应用使用独立身份，不自动导入正式版的资料库。

## 试用

1. 在 PR 的 macOS verification 成功运行中，下载 `Pasteory-AI-Preview-macOS-arm64` artifact，解压并打开 `Pasteory-QA.app`。需要 Apple Silicon 和 macOS 14 以上。QA 包使用构建机器生成的本地开发签名，未经过 Apple 公证。
2. 打开“设置 → AI 整理 → 模型连接”。Magpie 默认地址为 `http://127.0.0.1:3425/v1`；Ollama 为 `http://127.0.0.1:11434/v1`。其他服务使用完整的 HTTPS OpenAI 兼容 Base URL。凭据写入 macOS 钥匙串。
3. 获取模型，选择模型 ID。推理强度从接口声明的 `reasoning_levels` / `supported_reasoning_levels` 获取；接口未声明时仅使用自动模式，不猜测模型能力。
4. 修改默认 Prompt，测试连接并保存。连接测试仅使用合成文本，会记录用量。打开 AI 分析后才会发送允许的剪贴板内容。本机 Magpie 可能把请求转发给云端模型。
5. 使用“分析最近内容”或“分批整理全库”，检查建议中的具体操作，再应用所选变更。在分组右键菜单中编辑主题定义、重新检查成员或压缩旧资料。

## 分析和原子操作

每条资料使用稳定 UUID 与内容版本，包含标题、正文、备注、来源应用名称、复制时间和已有分组。图片和文件只提供元数据，不读取原文件，不做 OCR。逐条排除 AI 的内容、废纸篓和已识别的密钥被过滤。该过滤不保证识别所有敏感信息，应自行控制允许分析的资料。

默认分析最近 100 条不同内容，每批最多 50 条。初始请求按上下文预算缩短正文；当前批次的文本最多在本地加载 60,000 字符，模型可用 `clips_get` 的 `offset_chars` / `max_chars` 分页读取。超过 2 MiB 的单条正文保留预览。历史检索先提供正文预览，每次最多返回 20 条；模型读过的历史上下文不自动获得改动权限。现有分组目录先提供 20 个，再按需搜索主题和概况。

全库 5,000 条不会一次发送。任务保存 ID 列表、游标和草稿，每批重新执行有限轮工具调用，每次请求先检查 token 预算。关闭应用、暂停或预算耗尽后可以继续；配置或已读取资料版本变化时需放弃旧任务重新分析。后台任务仅在应用运行并唤醒时工作。

新增内容合并等待 30 秒，累计 5 条或等待 2 分钟后入队；自动分析至少间隔 5 分钟。定时分析默认间隔 30 分钟，无变化时跳过。手动和自动调用共用每日 token 上限。

| 原子工具 | 作用 |
| --- | --- |
| `clips_get` / `clips_search` | 受限地读取和检索资料 |
| `groups_get` / `groups_search` | 读取主题定义、概况、覆盖范围和代表成员 |
| `groups_create` | 创建 AI 分组草稿，返回 UUID |
| `groups_add_items` / `groups_remove_items` | 调整明确 ID 的成员关系 |
| `groups_update_overview` | 更新独立概况，并标记实际覆盖的成员 |
| `aggregations_create` | 把至少两条不同资料组合为可复用聚合 |
| `summaries_set` | 保存事实、推断和建议待办，每条附精确原文引用 |

模型调用上述工具形成 `AIChangeSet`，应用拥有真正的提交权。没有 `apply_plan`、任意 SQL、shell 或文件操作工具。这版工具在应用内部执行，尚不提供外部 MCP 服务或 CLI 接口。

应用在一个 SQLite 事务中校验并更新关系表、Clip JSON、搜索索引、AI 元数据和撤销记录；一条无效命令会使整批回滚。重复提交同一结果保持幂等。撤销只恢复这次修改的关系和 AI 元数据，保留后来修改的备注；成员关系或主题已被用户修改时，停止撤销并提示冲突。备份恢复保留分组与归纳，不导入依赖旧数据库的撤销事务。

用户修改的主题定义优先，AI 概况另存，修改定义后可重新检查成员。手动成员不能被 AI 移出；用户移出的成员加入该组排除记录。AI 可自动补充已有分组，但创建新组、聚合和移出操作仍进入预览。归纳引用可打开对应原文；原文变化后显示过期状态。

本版 AI 聚合保存本次选择的固定成员，不会按照名称自行吸收后续资料；后台自动补充模式针对已有 AI 分组。

## 生命周期

活动事实属于 Clip：最近使用时间以及用户复制、成功粘贴、显式打开和编辑事件。AI 更新概况、调整分组、后台扫描不刷新活动。旧资料使用已保存的最近复制和粘贴事实初始化，不把历史累计复制数当作近期频率。

界面只有三个阶段：**活跃 → 留存 → 归档**。时间节点不自动删除资料。压缩资格是独立属性。

| 预设 | 降权 | 可压缩 | 可归档 |
| --- | --- | --- | --- |
| 激进 | 3 天 | 7 天 | 30 天 |
| 标准 | 7 天 | 14 天 | 60 天 |
| 保守 | 14 天 | 30 天 | 120 天 |

可以修改时间节点、最近使用 / 频率 / 不同日期持续使用的权重、事件权重、频率统计窗口、Top K 数量与权重，以及分组阶段阈值。权重 0 关闭指标，其余归一化。使用频率和持续使用随最近使用程度一起衰减，旧项目不会因历史次数很多而永久活跃。

分组没有独立的“最后活动时间”。分组系数 = Top K 成员平均系数 × Top K 权重 + 全部成员平均系数 × 剩余权重。归档组折叠展示，并从快捷面板常用分组中隐藏；“保留此分组”可保持可见。用户仍能浏览归档资料，不按天数自动解散或删除分组。废纸篓原有 30 天保留规则继续独立运行。

## 共享内容和无损压缩

使用 SHA-256 寻址的不可变载荷，相当于硬链接的共享内容语义，不依赖文件系统硬链接。每个分组、聚合和无分组资料拥有独立引用，引用记录自己使用原文还是压缩副本。收藏、置顶、废纸篓和合并恢复记录保护所需原文。

同一材料同时在 A / B 组时，未压缩前共享一份原文。压缩 A 后得到一份经过解压和校验的共享压缩副本，B 仍持有原文。B 也压缩后，先提交数据库中的压缩引用，再确认原文引用数和读取租约归零、磁盘上的压缩副本校验正确，才释放原文载荷。读取按需解压，正文不会被语义摘要替换。

压缩不删除 Clip、标题、备注、搜索预览或其他分组关系，因此统计中的“原文载荷回收”不等于删除所有可见文本，也不保证每种小载荷都节省磁盘空间。文件引用只压缩保存的引用数据，不修改原文件。

备份格式升级为 v5，包含普通分组、AI 主题和归纳、共享载荷 manifest、原文与压缩副本，覆盖部分分组已压缩的场景；兼容导入 v1–v4。清理通过存活引用校对后回收无引用载荷，删除一个分组不会销毁其他分组需要的内容。

## 用量与边界

用量页提供近 7 天图表、每日预算、最近调用和自定义单价估算。缓存 token 是输入的子集，推理 token 可能是输出的子集，均不重复累计。服务商没有返回 usage、超时或失败时记录保守估算，不显示为零。订阅额度不当作现金账单，缺少单价时不显示虚构费用。

此版只使用支持 OpenAI Chat Completions 及 function calling 的接口；Magpie 可代为路由到其支持的模型。没有自动安装或接管 Magpie，没有网页抓取、向量数据库、图片理解、外部 MCP / CLI 或无人值守的内容删除。真实服务端的配额和费用以服务商账单为准。

## 验证

`swift test` 包含可移植 AI 逻辑测试与 macOS SQLite 集成测试；GitHub Actions 另外执行 Release 构建、应用打包身份检查、本地化检查和中英文原生截图。Linux 可运行 AI 逻辑测试，不能替代原生 macOS 应用类型检查。
