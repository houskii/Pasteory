# AI 整理预览版

这一版在原生 macOS 应用中提供模型配置、智能分组、资料聚合、带依据的归纳，以及内容生命周期和共享载荷的无损压缩。AI 默认关闭，自动压缩默认关闭。源码通过独立开发分支和草稿 PR 交付；QA 应用使用独立身份，不自动导入正式版的资料库。

## 0.1.39 的 Prompt 展示与分组管理

资料库选中 AI 分组后，搜索框下方会显示“分组 Prompt（主题定义）”，支持展开、复制和编辑。资料库顶部的“管理 AI 分组”列出全部 AI 分组及其定义，支持单选、多选、全选与取消全选；此处的全选范围是全部 AI 分组，不包含普通文件夹或规则分组。

“清理所选分组”在本地移除所选 AI 组及归属关系，保留原文、备注、手动文件夹和原始时间值，并记录撤销操作。用户明确选择的组可以包含保留组、手动定义的 AI 组和手动加入 AI 组的成员。排除 AI 分析的内容也可以解除所选 AI 归属，但不会发送给模型。

“生成重新分组方案”固定使用所选组成员的去重范围，不受最近 Top N 限制。查看当前模型、全局 Prompt、固定规则与发送范围后，可以生成方案；生成或暂停期间旧组继续可用，方案应用时才在一个事务中清理旧组并建立新归属，支持整体撤销。断点保存所选组版本、成员范围和清理计划；版本发生变化时停止，保留现有数据。

未选组的主题定义保持稳定，所选内容可以匹配到已有主题。还有主题名额且至少有 3 条可分析内容时，会统一规划主题；未选组已占满名额时，复用现有主题，不强制新增分组。没有匹配的内容可以保留未分组或候选主题。资料被多个所选组收录时只分析一次。

此版本不自动清理当前资料库，不自动开始重新分组，也没有扩大现有 AI 发送字段。

## 0.1.38 的分组栏位置

分组栏只提供左侧和右侧两种位置，快捷面板和资料库使用相同设置。移除搜索框下方横排；旧的横排和左侧竖排设置均迁移到左侧。Profile 切换、分组搜索及分组项位于同一侧栏内，极简视图继续隐藏侧栏。切换位置保留搜索、选中项和阅读位置，右侧分隔线按相反方向拖动来调整宽度。

## 0.1.36 的视图溢出与新内容提示

视图不超过 3 个时平铺展示；更多视图使用可横向滚动的标签栏，并提供全部视图菜单。选中的视图会滚动到可见位置，不压缩所有标签来凑宽度。当前产品提供 3 个内置视图，溢出组件通过 5 个视图的隔离样例验证。

AI 分组列表不再显示成员总数，改为仅在有新增未查看成员时显示“新内容”。打开该组后清除提示；升级时以已有成员建立基线，不把历史资料全部标新。概况更新、重命名和成员移出不会生成新增提示。快捷键以独立的按键框展示，Profile 快捷键只在设置中显示。

## 0.1.35 的导航调整

“未分组”是没有 AI 主题归属的筛选条件，不进入左右切组顺序，也不占快捷键编号。可在分组搜索中开启此筛选，或通过“全部内容”的右键菜单进入。

竖排模式的视图切换和分组搜索位于分组栏顶部。默认 Option-1～9 切换当前视图中按显示顺序排列的前 9 个分组，Option-`（1 左侧的 ～ 键，无需 Shift）返回全部内容。Profile 默认使用 Control-Option-1～9，快捷键只在设置中展示，配置按视图标识保存，不限定为 3 个；超过 9 个可自设组合键。目前提供 3 个内置视图。可以在“设置 → 快捷键”中修改或清除，界面提示随配置更新。

分类使用固定保护规则、全局整理偏好以及各组的主题定义。分组定义可包含收录边界和排除项；编辑 AI 分组可以查看或修改。主题规划使用独立的固定规划指令，要求复用受保护主题、控制主题总数并保留未分组内容。

## 0.1.34 的分组与自动整理

分组入口统一使用 `AI` 文字标记。常用视图默认展示 3 个推荐 AI 组，AI 视图查看全部 AI 主题，极简视图隐藏分组栏。分组搜索仍可访问低频组；侧栏支持 180–320 pt 拖动宽度及紧凑行高。视图切换分别保存查询、选中项与阅读位置。

正式 AI 主题以 6～8 个为目标，上限为 8 个；小主题先进入候选，通常至少有 3 条不同内容才建立正式主题。首次较大范围整理先规划全局主题，再分批归类。已有超过上限的主题通过“复核主题”生成完整收敛建议，检查后在单个事务中应用，也可整体撤销。活跃组、用户锁定的主题和当前阅读的组保持稳定。合并后不适合任何主题的内容进入“未分组”，原文继续保留。

新增整理使用持久化内容版本队列，范围严格限定为队列中的 ID。重复复制相同正文只更新真实使用活跃度。每条输入记录归属、未匹配原因或候选主题；不再把未归组等同于漏处理。自动分类仅做主题归类，不新建聚合或摘要。

闲时整理是独立开关，默认窗口为本地时间 01:00–02:00，空闲 5 分钟、设备唤醒且未开启低电量模式时运行。每晚共享 100 条、10 分钟和 30 万 token 上限，并受已有每日总预算约束。设备休眠、用户恢复操作、窗口结束或额度耗尽时，在批次边界保存进度。错过窗口顺延下一晚，不在白天补跑。每 7 天在相同窗口复核低活跃主题；手动任务和新增内容优先。新功能保留已有用户的自动整理开关与模型配置。

推荐按真实使用活跃度计算，在面板打开期间保持顺序。当前 Top 3、近 7 天仍有主动使用、手动锁定、当前阅读及退出推荐位后的 7 天保护期内的主题不自动重组。后台改组与概况更新不增加活跃度，也不改 SQLite 中的原始使用时间。结构调整仍遵从预览模式，已有组成员的自动补充遵从用户选择的应用方式。

“未分组”指没有 AI 主题归属；手动文件夹和图片、链接等规则筛选不改变这个定义。未匹配内容在正文、规则和主题目录未变时跳过重复分析。

OpenAI 兼容接入可填写 `https://api.deepseek.com`，调用模型目录返回的 ID。连接测试仅发送合成文本；凭据继续仅存于钥匙串。

## 试用

1. 在 PR 的 macOS verification 成功运行中，下载 `Pasteory-AI-Preview-macOS-arm64` artifact，解压并打开 `Pasteory-QA.app`。需要 Apple Silicon 和 macOS 14 以上。QA 包使用构建机器生成的本地开发签名，未经过 Apple 公证。
2. 打开“设置 → AI 整理 → 模型连接”。Magpie 默认地址为 `http://127.0.0.1:3425/v1`；Ollama 为 `http://127.0.0.1:11434/v1`。其他服务使用完整的 HTTPS OpenAI 兼容 Base URL。凭据写入 macOS 钥匙串。
3. 获取模型，选择模型 ID。推理强度从接口声明的 `reasoning_levels` / `supported_reasoning_levels` 获取；接口未声明时仅使用自动模式，不猜测模型能力。
4. 修改默认 Prompt，测试连接并保存。连接测试仅使用合成文本，会记录用量。打开 AI 分析后才会发送允许的剪贴板内容。本机 Magpie 可能把请求转发给云端模型。
5. 使用“分析最近内容”或“分批整理全库”，检查建议中的具体操作，再应用所选变更。在分组右键菜单中编辑主题定义、重新检查成员或压缩旧资料。

## 当前发送给分类 Agent 的内容

每批请求包含全局整理偏好、当前批次资料、已有 AI 分组目录、候选主题及读写范围限制。每条资料的字段为：稳定 ID、版本指纹、显示标题、正文、用户备注、来源应用名称、内容类型、最近复制时间、已有分组 ID 和截断标记。备注及来源应用名称分别受发送开关控制。

显示标题优先使用手动标题，未设置时使用自动标题，因此已回填的链接解析标题能够进入 AI 输入。复制来源目前只有 App 名称，不包含来源应用的进程信息、网页上下文、会话标题、选区、实体列表或采集策略。结构化的 `CapturedSourceContext` 及链接解析资源、解析尝试的完整结果尚未映射到 AI 文档；Agent 也没有任意打开网页或访问浏览器会话的工具。

普通文本和代码可以按需在本地加载正文，每条最多 60,000 字符；首批正文通常按预算截到 2,400 字符以内，可用受限工具分页读取。单条链接正文会去除查询参数和片段。文件仅提供文件名；图片与混合内容使用元数据占位，不发送原始图像或文件字节，也不做 OCR。这里没有扩大现有发送范围。

## 分析和原子操作

每条资料使用稳定 UUID 与内容版本，包含标题、正文、备注、来源应用名称、复制时间和已有分组。图片和文件只提供元数据，不读取原文件，不做 OCR。逐条排除 AI 的内容、废纸篓和已识别的密钥被过滤。该过滤不保证识别所有敏感信息，应自行控制允许分析的资料。

默认手动分析最近 100 条不同内容；实际执行每批最多 20 条。初始请求按上下文预算缩短正文；当前批次的文本最多在本地加载 60,000 字符，模型可用 `clips_get` 的 `offset_chars` / `max_chars` 分页读取。超过 2 MiB 的单条正文保留预览。历史检索先提供正文预览，每次最多返回 20 条；模型读过的历史上下文不自动获得改动权限。现有主题以完整轻量目录提供，需要时再读取定义、概况与代表内容。

全库 5,000 条不会一次发送。任务保存 ID 列表、游标和草稿，每批重新执行有限轮工具调用，每次请求先检查 token 预算。关闭应用、暂停或预算耗尽后可以继续；批量大小与预算调整允许继续原任务；模型、Prompt、发送范围或内容版本变化时需重新准备任务。后台任务仅在应用运行并唤醒时工作。

新增内容合并等待 30 秒，累计 5 条或等待 2 分钟后入队；自动分析至少间隔 5 分钟。闲时整理使用上面的夜间窗口与每 7 天复核周期。手动和自动调用共用每日 token 上限。

| 原子工具 | 作用 |
| --- | --- |
| `clips_classify` / `themes_propose` | 记录逐条结果和跨批次候选主题 |
| `clips_get` / `clips_search` | 受限地读取和检索资料 |
| `groups_get` / `groups_search` | 读取主题定义、概况、覆盖范围和代表成员 |
| `groups_create` | 创建 AI 分组草稿，返回 UUID |
| `groups_add_items` / `groups_remove_items` | 调整明确 ID 的成员关系 |
| `groups_update_overview` | 更新独立概况，并标记实际覆盖的成员 |
| `aggregations_create` | 把至少两条不同资料组合为可复用聚合 |
| `summaries_set` | 保存事实、推断和建议待办，每条附精确原文引用 |

模型调用上述工具形成 `AIChangeSet`，应用拥有真正的提交权。没有 `apply_plan`、任意 SQL、shell 或文件操作工具。这版工具在应用内部执行，尚不提供外部 MCP 服务或 CLI 接口。

应用在一个 SQLite 事务中校验并更新关系表、Clip JSON、搜索索引、AI 元数据和撤销记录；一条无效命令会使整批回滚。重复提交同一结果保持幂等。撤销只恢复这次修改的关系和 AI 元数据，保留后来修改的备注；成员关系或主题已被用户修改时，停止撤销并提示冲突。备份恢复保留分组与归纳，不导入依赖旧数据库的撤销事务。

用户修改的主题定义优先，AI 概况另存，修改定义后可重新检查成员。手动成员不能被 AI 移出；用户移出的成员加入该组排除记录。AI 可自动补充已有分组，但创建新组、聚合和移出操作仍进入预览。归纳引用可打开对应原文；原文变化后显示过期状态。

本版 AI 聚合保存本次选择的固定成员，不会按照名称自行吸收后续资料；后台自动补充模式针对已有 AI 分组。

## 生命周期

活动事实属于 Clip：最近使用时间以及用户复制、成功粘贴、显式打开和编辑事件。AI 更新概况、调整分组、后台扫描不刷新活动。旧资料使用已保存的最近复制和粘贴事实初始化，不把历史累计复制数当作近期频率。

界面只有三个阶段：**活跃 → 留存 → 归档**。时间节点不自动删除资料。压缩资格是独立属性。

| 预设 | 降权 | 可压缩 | 可归档 |
| --- | --- | --- | --- |
| 激进 | 3 天 | 7 天 | 30 天 |
| 标准 | 7 天 | 14 天 | 60 天 |
| 保守 | 14 天 | 30 天 | 120 天 |

可以修改时间节点、最近使用 / 频率 / 不同日期持续使用的权重、事件权重、频率统计窗口、Top K 数量与权重，以及分组阶段阈值。权重 0 关闭指标，其余归一化。使用频率和持续使用随最近使用程度一起衰减，旧项目不会因历史次数很多而永久活跃。

分组没有独立的“最后活动时间”。分组系数 = Top K 成员平均系数 × Top K 权重 + 全部成员平均系数 × 剩余权重。归档组折叠展示，并从快捷面板常用分组中隐藏；“保留此分组”可保持可见。用户仍能浏览归档资料，不按天数自动解散或删除分组。废纸篓原有 30 天保留规则继续独立运行。

## 共享内容和无损压缩

使用 SHA-256 寻址的不可变载荷，相当于硬链接的共享内容语义，不依赖文件系统硬链接。每个分组、聚合和无分组资料拥有独立引用，引用记录自己使用原文还是压缩副本。收藏、置顶、废纸篓和合并恢复记录保护所需原文。

同一材料同时在 A / B 组时，未压缩前共享一份原文。压缩 A 后得到一份经过解压和校验的共享压缩副本，B 仍持有原文。B 也压缩后，先提交数据库中的压缩引用，再确认原文引用数和读取租约归零、磁盘上的压缩副本校验正确，才释放原文载荷。读取按需解压，正文不会被语义摘要替换。

压缩不删除 Clip、标题、备注、搜索预览或其他分组关系，因此统计中的“原文载荷回收”不等于删除所有可见文本，也不保证每种小载荷都节省磁盘空间。文件引用只压缩保存的引用数据，不修改原文件。

备份格式升级为 v5，包含普通分组、AI 主题和归纳、共享载荷 manifest、原文与压缩副本，覆盖部分分组已压缩的场景；兼容导入 v1–v4。清理通过存活引用校对后回收无引用载荷，删除一个分组不会销毁其他分组需要的内容。

## 用量与边界

用量页提供近 7 天图表、每日预算、最近调用和自定义单价估算。缓存 token 是输入的子集，推理 token 可能是输出的子集，均不重复累计。服务商没有返回 usage、超时或失败时记录保守估算，不显示为零。订阅额度不当作现金账单，缺少单价时不显示虚构费用。

此版只使用支持 OpenAI Chat Completions 及 function calling 的接口；Magpie 可代为路由到其支持的模型。没有自动安装或接管 Magpie，没有网页抓取、向量数据库、图片理解、外部 MCP / CLI 或无人值守的内容删除。真实服务端的配额和费用以服务商账单为准。

## 验证

`swift test` 包含可移植 AI 逻辑测试与 macOS SQLite 集成测试；GitHub Actions 另外执行 Release 构建、应用打包身份检查、本地化检查和中英文原生截图。Linux 可运行 AI 逻辑测试，不能替代原生 macOS 应用类型检查。

未完成的手动任务会保留固定内容范围和批次进度。此时再次发起整理，主界面会提示先继续或放弃保存的任务；暂停、失败和正在运行分别显示，失败原因会随进度保存。快捷面板和资料库均提供续跑入口。主题规划结果未通过校验时，模型最多修正两次，沿用同一输入范围和预算；仍失败时保留进度，原有分组继续可用。

全选 AI 分组时，范围是这些组现有成员的去重集合，未分组内容不会自动包含在内。管理面板同时显示全库总数、AI 组成员数和未入组数。若不满意现有主题，可从资料库的 AI 整理菜单打开“重新整理全库…”，检查全局 Prompt、模型、可分析条数和目标主题数后生成全库方案。此范围包含未分组内容，不受 Top N 限制；生成期间保留旧组，用户检查后整体应用，可撤销。“沿用现有主题分析全库”则保留主题定义，对全库内容继续分类。

AI 常驻索引读取轻量元数据，不读取 `items` 中的内嵌数据或附件载荷；保留预览、标题、备注、来源、活动记录和分组关系，以维持版本校验和分组导航。分析批次通过 `aiContext` 按需读取完整正文。搜索先对元数据排序，再只读取当前结果页的完整记录。
