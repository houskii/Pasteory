# 活跃度算法设计

状态：设计稿。0.1.52 交付图片排版与纯文本操作修复，尚未切换本方案的评分。

## 当前新内容为什么显示 68%

现有标准策略见 `Sources/PasteoryAI/Lifecycle.swift`：最近使用占 60%，使用频率占 25%，不同日期的持续使用占 15%。

新采集的内容记录了一次复制。此时最近使用值为 1，频率值为 `ln(2) / ln(21)`，持续使用值为 `1 / 7`。

```text
100 × (0.60 + 0.25 × ln(2) / ln(21) + 0.15 / 7)
= 67.8346%
```

因此新内容显示约 68%。这个初始值不符合“刚复制的内容最需要使用”的预期。

资料库的“活跃度”显示分值，“活跃度前 N%”显示全库排名。同分内容并列，排名百分比包含全部同分内容。

## 推荐参数

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| 新内容分值 | 100% | 首次采集时直接设为满分 |
| 普通内容半衰期 | 72 小时 | 没有再次使用时，72 小时降到 50% |
| 再次复制的系数增量 x | 0.2 | 复制一次增加 0.2，延缓后续衰减 |
| 成功粘贴的系数增量 y | 0.4 | 粘贴比单纯复制体现更明确的使用意图 |
| 最大系数 | 4 | 控制反复使用带来的累计加成 |
| 加成的半衰期 | 7 天 | 加成也随时间衰减，逐渐回到普通内容的水平 |

首次采集的复制不再额外计入复用加成。之后每次真实复制、成功粘贴，分值恢复到 100%，重新计时，同时增加对应系数。Pasteory 粘贴时内部写入剪贴板只计这一次粘贴事件。

## 计算公式

保存最近一次使用时间 `lastUsedAt`，以及该时刻的复用加成 `b`。新内容的 `b = 0`，最大值为 3。

设 `d` 为距最近一次使用的天数，最小取 0：

```text
当前加成 = b × 2^(-d / 7)
当前系数 k = 1 + 当前加成
活跃度 A = clamp(100 × 2^(-d / (3 × k)), 0, 100)
```

每次使用先衰减原有加成，再累加本次增量：

```text
复制后：b = min(3, 当前加成 + 0.2)
粘贴后：b = min(3, 当前加成 + 0.4)
lastUsedAt = 本次使用时间
```

每次使用后的 `d = 0`，所以分值为 100%。系数增量用于延长后续保温时间；分值不会超过 100%。停止使用后，分值和加成都会逐渐降低。

## 衰减计算

下表从最近一次使用开始计算，之后没有再操作。“再次复制”和“成功粘贴”两列分别假设原加成为 0，本次只增加一次对应事件。

| 距最近一次使用 | 普通内容 | 再次复制一次 | 成功粘贴一次 |
| --- | ---: | ---: | ---: |
| 刚使用 | 100.00% | 100.00% | 100.00% |
| 6 小时 | 94.39% | 95.28% | 95.93% |
| 12 小时 | 89.09% | 90.75% | 91.97% |
| 24 小时 | 79.37% | 82.23% | 84.40% |
| 72 小时 | 50.00% | 54.69% | 58.61% |
| 7 天 | 19.84% | 22.99% | 25.98% |
| 14 天 | 3.94% | 4.59% | 5.28% |
| 30 天 | 0.10% | 0.10% | 0.11% |

例如，普通内容在第 3 天降到 50%。这时再复制一次，会恢复到 100%，系数变为 1.2。再过 3 天不使用，分值为 54.69%。如果这次是成功粘贴，系数变为 1.4，再过 3 天为 58.61%。

## 计算与现有数据

- 使用事件发生时更新本条记录的时间与加成。显示、排序时按当前时间计算，不需要定期更新全库数据库。
- 分组继续汇总成员分值，复用现有 Top K 均值和全部成员均值的加权方式。内容分值与分组分值都限定在 0～100%。
- 旧内容从已保存的真实使用事件重放加成；历史记录不足时按普通内容计算，不用终身复制次数推造历史事件。
- OCR、AI 整理、链接解析、列表浏览不更新使用时间，也不增加系数。
- 本方案定义活跃度分值。留存、压缩与归档继续使用现有时间节点和收藏、置顶保护规则。

参数可以作为高级设置调整。优先保留“半衰期、复制增量、粘贴增量”三个用户可理解的选项，加成上限和衰减周期使用默认值。
